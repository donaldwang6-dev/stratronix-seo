PAA 远程诊断 SOP

30 分钟内远程解决 80% 故障 · 基于 SSH 的标准分流流程
发布时间: 2026 年 8 月 10 日 · 类别: 售后、SOP、远程诊断
适用版本: STRATRONIX STA-100 PAA（全部固件版本）

为什么需要这份 SOP

PAA 的设计目标之一就是支持 SSH 远程诊断。80% 的故障可以在 30 分钟内远程解决，无需寄回设备。这既保障你的团队产能，也压低我们的终身售后成本——这是我们 399 美元统一售价、2 年质保承诺的核心支撑。

本文档是 STRATRONIX 售后工程师团队使用的标准作业程序。IT 管理员可以直接参照执行，也可以申请远程会诊，由我们的工程师与你一起诊断。

📌 开始之前: 请确认 SSH 已启用且售后公钥已安装。如未启用，请参考 5 分钟上手指南。

一、初步分流（5 分钟）

1.1 连通性检查

# 从你的工作站执行
ssh paa@<paa-ip-address>
# 连接成功即可继续。

如果 SSH 失败：

  • 检查网线 / Wi-Fi 是否连接
  • 通过路由器 DHCP 表核对 PAA IP 地址
  • 确认防火墙未屏蔽 22 端口
  • 断电重启 PAA（拔电源，等 10 秒，重新插入）

1.2 系统状态快照

# 在 PAA 的 SSH 会话内执行
paa-status
# 预期输出：8 项健康检查全部显示绿色对勾

paa-status 命令运行 8 项健康检查（CPU、内存、磁盘、网络、LLM 服务、Watchdog、温度、授权），并输出单行汇总。

二、五大诊断类别

类别出现频率平均修复时长
LLM 服务无响应约 40%5-10 分钟
网络 / SSH 访问问题约 20%5-15 分钟
性能下降约 15%10-20 分钟
磁盘 / 存储告警约 15%5-10 分钟
硬件故障（罕见）约 10%需 RMA

三、类别 1：LLM 服务无响应

3.1 症状

用户反馈：AI 变慢、AI 不回复、聊天界面报 503 错误。

3.2 诊断

systemctl status openclaw-llm
# 检查服务是否活跃，最近日志是否有错误

journalctl -u openclaw-llm --since "10 minutes ago"
# 查看最近日志

paa-llm-health
# 详细健康状态：模型是否已加载？显存占用？请求队列深度？

3.3 常用修复

修复 3.3.1 — 重启 LLM 服务

sudo systemctl restart openclaw-llm
# 等 30 秒后验证：
paa-llm-health

修复 3.3.2 — 清理残留请求队列

sudo systemctl restart openclaw-queue
paa-llm-health

修复 3.3.3 — 重新加载模型（罕见）

# 仅在模型文件损坏或显存不稳定时执行
sudo paa-reload-model
# 约 60 秒

四、类别 2：网络 / SSH 访问

4.1 症状

用户反馈：连不上、SSH 超时、Web UI 无法访问。

4.2 诊断

# 在 PAA 本地控制台（HDMI + 键盘）
ip addr show
# 核对 IP 地址

systemctl status sshd
# 确认 SSH 守护进程运行

systemctl status openclaw-web
# 确认 Web UI 在 8080 端口运行

4.3 常用修复

修复 4.3.1 — 重启网络服务

sudo systemctl restart NetworkManager
sudo systemctl restart sshd

修复 4.3.2 — 重置为 DHCP

sudo nmcli connection reload
sudo nmcli connection up "Wired connection 1"

修复 4.3.3 — 重置防火墙（罕见）

sudo paa-firewall-reset
# 恢复默认防火墙规则

五、类别 3：性能下降

5.1 症状

用户反馈：AI 回复比平时慢、部分请求超时。

5.2 诊断

paa-perf-check
# 输出：tokens/秒、队列深度、显存占用、温度

top -b -n 1 | head -20
# 检查失控进程

journalctl --since "1 hour ago" | grep -i "error\|warn"

5.3 常用修复

修复 5.3.1 — 重启可能内存泄漏的服务

sudo systemctl restart openclaw-llm openclaw-queue openclaw-cache

修复 5.3.2 — 清理缓存

sudo paa-cache-clear
# 保留模型加载，清理请求缓存

修复 5.3.3 — 降低并发请求上限

sudo paa-tune --max-concurrent=4
# 默认 8；显存紧张时下调

六、类别 4：磁盘 / 存储

6.1 症状

用户反馈：无法保存文件、磁盘空间低、日志写入失败。

6.2 诊断

df -h
# 查看文件系统占用

du -sh /var/log/openclaw/*
# 查看日志目录大小

paa-storage-report
# 详细：空间分布、预计耗尽日期

6.3 常用修复

修复 6.3.1 — 日志轮转

sudo journalctl --vacuum-size=500M
sudo paa-log-rotate

修复 6.3.2 — 清理旧对话缓存

sudo paa-cache-clear --conversations --older-than=30d

修复 6.3.3 — 扩容（进阶）

对于对话历史超过 1TB 的部署，请联系 sales@stratronix.ai 获取存储扩容方案。

七、类别 5：硬件故障（需 RMA）

7.1 症状

设备无法开机，或 paa-status 在硬件健康检查（温度、NVMe SMART、风扇）显示红色。

7.2 诊断

paa-hardware-diag
# 全面的硬件测试（耗时 3 分钟）

sudo smartctl -A /dev/nvme0n1
# NVMe 健康度

7.3 RMA 流程

  1. 发送邮件至 rma@stratronix.ai，附上 paa-hardware-diag 输出与 PAA 序列号
  2. 1 个工作日内收到预付运费标签
  3. 寄出设备；收到后 3 个工作日内发出替换机
  4. 2 年质保覆盖全部硬件故障：NVMe、RAM、风扇、电源
📌 2 年免费质保: 质保期内所有硬件故障免费维修或更换。非质量问题不退换。邮件 support@stratronix.ai 报修。

八、申请远程售后会诊

如果你参照本 SOP 仍无法解决问题，我们的售后团队可以远程接入。会诊通过 SSH + 屏幕共享进行，你始终保留设备完整控制权。

8.1 申请方式

  1. 发送邮件至 support@stratronix.ai，提供：PAA 序列号、问题描述、paa-status 输出
  2. 4 个工作时内（工作时间 1 小时内）收到预约链接
  3. 加入远程会诊，工程师与你一起诊断

8.2 SLA 目标

等级响应时间解决时间
紧急（服务中断）1 小时4 小时
高（性能下降）4 小时24 小时
中（单项功能故障）1 个工作日3 个工作日
低（外观 / 改进建议）3 个工作日下一版固件

九、自愈能力

50% 的 PAA 故障会被内置 Watchdog 自动恢复，无需任何人工干预。Watchdog 监控：

  • LLM 服务响应（卡死时自动重启）
  • 内存压力（90% 阈值自动清理缓存）
  • 磁盘空间（85% 阈值自动轮转日志）
  • 温度（85°C 自动降频，95°C 自动关机）
  • 网络连接（链路断开自动重连）

可通过 paa-watchdog-log 查看 Watchdog 处置记录。

十、升级路径

如果售后团队 24 小时内无法远程解决、且设备在质保期内，我们将：

  1. 1 个工作日内发出预付运费的替换机
  2. 将你的配置、模型与对话历史迁移至替换机
  3. 承担原设备退货运费
  4. 若替换机仍出现同类故障，按比例退还质保费用
