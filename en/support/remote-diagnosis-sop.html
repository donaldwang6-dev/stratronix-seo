PAA Remote Diagnosis SOP

Resolve 80% of PAA issues in 30 minutes · SSH-based standard triage procedure
Published: 10 August 2026 · Category: Support, SOP, Remote Diagnosis
Applies to: STRATRONIX STA-100 PAA (all firmware versions)

Why this SOP exists

PAA is designed to be diagnosable remotely via SSH. 80% of issues are resolvable within 30 minutes without shipping the unit. This keeps your team's productivity high and our lifetime support cost low — part of our $399 USD, 2-year warranty commitment.

This document is the standard operating procedure used by STRATRONIX support engineers. IT administrators can use it directly, or you can request a remote session where our engineer drives the diagnosis with you.

📌 Before you start: Make sure SSH access is enabled and you have the support key installed. See the 5-minute setup guide if you have not yet enabled SSH.

1. Initial Triage (5 minutes)

1.1 Connectivity check

# From your workstation
ssh paa@<paa-ip-address>
# If connection succeeds, you are good to proceed.

If SSH fails:

  • Check physical network cable / Wi-Fi connection
  • Verify the PAA IP address via your router's DHCP table
  • Confirm SSH port 22 is not blocked by firewall
  • Power-cycle the PAA (unplug, wait 10 seconds, plug back)

1.2 System status snapshot

# Run inside PAA SSH session
paa-status
# Expected output: green checkmarks for all 8 health checks

The paa-status command runs 8 health checks (CPU, memory, disk, network, LLM service, watchdog, temperature, license) and produces a single-line summary.

3. Category 1 — LLM Service Unresponsive

3.1 Symptom

User reports: "AI is slow" / "AI does not respond" / "Error 503 from chat interface".

3.2 Diagnosis

systemctl status openclaw-llm
# Check if service is active, recent logs show errors

journalctl -u openclaw-llm --since "10 minutes ago"
# Recent log output

paa-llm-health
# Detailed health: model loaded? VRAM usage? Request queue depth?

3.3 Common fixes

Fix 3.3.1 — Restart the LLM service

sudo systemctl restart openclaw-llm
# Wait 30 seconds, then verify:
paa-llm-health

Fix 3.3.2 — Clear stale request queue

sudo systemctl restart openclaw-queue
paa-llm-health

Fix 3.3.3 — Reload model (rare)

# Only if model file corrupted or VRAM unstable
sudo paa-reload-model
# Takes ~60 seconds

4. Category 2 — Network / SSH Access

4.1 Symptom

User reports: "Cannot connect" / "SSH timeout" / "Web UI unreachable".

4.2 Diagnosis

# From PAA local console (HDMI + keyboard)
ip addr show
# Verify IP address

systemctl status sshd
# Verify SSH daemon running

systemctl status openclaw-web
# Verify web UI running on port 8080

4.3 Common fixes

Fix 4.3.1 — Restart network services

sudo systemctl restart NetworkManager
sudo systemctl restart sshd

Fix 4.3.2 — Reset IP to DHCP

sudo nmcli connection reload
sudo nmcli connection up "Wired connection 1"

Fix 4.3.3 — Open firewall port (rare)

sudo paa-firewall-reset
# Restores default firewall rules

5. Category 3 — Performance Degradation

5.1 Symptom

User reports: "AI responses are slower than usual" / "Some requests time out".

5.2 Diagnosis

paa-perf-check
# Output: tokens/sec, queue depth, VRAM usage, temperature

top -b -n 1 | head -20
# Check for runaway processes

journalctl --since "1 hour ago" | grep -i "error\|warn"

5.3 Common fixes

Fix 5.3.1 — Restart memory-leaking services

sudo systemctl restart openclaw-llm openclaw-queue openclaw-cache

Fix 5.3.2 — Clear cache

sudo paa-cache-clear
# Keeps model loaded, clears request cache

Fix 5.3.3 — Reduce concurrent request limit

sudo paa-tune --max-concurrent=4
# Default is 8; reduce if VRAM-constrained

6. Category 4 — Disk / Storage

6.1 Symptom

User reports: "Cannot save files" / "Low disk space warnings" / "Logs not being written".

6.2 Diagnosis

df -h
# Check filesystem usage

du -sh /var/log/openclaw/*
# Check log directory size

paa-storage-report
# Detailed: where space is used, projected exhaustion date

6.3 Common fixes

Fix 6.3.1 — Rotate logs

sudo journalctl --vacuum-size=500M
sudo paa-log-rotate

Fix 6.3.2 — Clean old conversation cache

sudo paa-cache-clear --conversations --older-than=30d

Fix 6.3.3 — Expand storage (advanced)

For deployments exceeding 1TB of conversation history, contact sales@stratronix.ai for storage expansion options.

7. Category 5 — Hardware Fault (RMA Required)

7.1 Symptom

Unit does not power on, or paa-status reports RED on hardware health checks (temperature, NVMe SMART, fan).

7.2 Diagnosis

paa-hardware-diag
# Comprehensive hardware test (takes 3 minutes)

sudo smartctl -A /dev/nvme0n1
# NVMe health

9. Self-Healing Capabilities

50% of PAA issues are resolved automatically by the built-in watchdog without any user intervention. The watchdog monitors:

  • LLM service responsiveness (auto-restart on hang)
  • Memory pressure (auto-clear cache at 90% threshold)
  • Disk space (auto-rotate logs at 85% threshold)
  • Temperature (auto-throttle at 85°C, shutdown at 95°C)
  • Network connectivity (auto-reconnect on link loss)

You can review watchdog actions via paa-watchdog-log.
